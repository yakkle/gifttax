# 해외 상장 ETF 지원: 커밋 단위 작업 계획

진행 순서: 구현 → 검증 → 변경 내용·검증 결과 제시 → 사용자 승인 → 커밋 → 해시 보고 → 다음 태스크.
각 태스크는 명시적 승인 후에만 커밋하며, 모든 커밋 전에 `ruff check .`를 통과한다.
커밋 메시지는 작업에 맞는 Conventional Commit 접두사와 한글 설명으로 작성한다.
기존 사용자 변경인 `docs/RELEASE_CHECKLIST.md`와 미추적 `uv.lock`은 보존하고 커밋에서 제외한다.

## 후속 태스크 7: 계산 명세와 개발 지침 분리

- 목적: 도메인 계산 규칙의 기준 문서를 명확히 하고 AGENTS.md의 책임을 에이전트 개발 지침으로 한정한다.
- 변경 범위: AGENTS.md의 주식·ETF 평가, 환율·단위·휴일·반올림·계산 가능일 규칙을 `docs/CALCULATION_SPEC.md`로 옮긴다. API 예시는 README, PDF 형식은 `PDF_REPORT_SPEC.md`, 증여세 엔진의 현황과 향후 설계는 `TAX_ENGINE.md`를 기준으로 정리한다.
- AGENTS.md에는 프로젝트 개요, 레이어 책임, 개발·검증·승인 절차와 관련 명세 링크를 남긴다. 현재 구현과 향후 계획을 구분하고 문서 간 중복·불일치를 제거한다.
- 검증 방법: 구현 및 기존 테스트와 명세 대조, Markdown 상대 링크 확인, 문서 diff 검토, `ruff check .`.
- 예정 커밋 메시지: `docs: 계산 규칙을 전용 명세로 분리하고 에이전트 지침 정리`.
- 태스크 5·6 이후 별도 구현·검증·승인·커밋으로 진행한다. 현재 태스크에서 계산 규칙 이동을 수행하지 않는다.

예상 증여세 엔진 구현, DB 변경, 배포는 범위에 포함하지 않는다.
